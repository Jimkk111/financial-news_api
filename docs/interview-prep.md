# 后端面试准备：MySQL / MyBatis-Plus / Redis 经典问题

> 适用：全栈实习生/初级后端。每题给"30 秒答法"，能结合本项目的都标了代码位置——
> 面试时把答案落到自己项目上，可信度远高于背概念。
> ⭐ = 必背高频，面试官几乎必问。

## 一、MySQL

### ⭐1. 索引的底层结构是什么？为什么用 B+ 树？
**答**：InnoDB 用 B+ 树。对比记忆：
- 哈希表：等值快但不支持范围查询和排序；
- 二叉/红黑树：数据量大时树太高，磁盘 IO 次数多；
- B+ 树：矮胖（3 层可存千万级数据），非叶子节点只存键、叶子节点存数据且用链表串联——**范围查询和排序高效**。
**结合项目**：news 表的 `uk_url` 唯一索引、`idx_publish_time` 普通索引都是 B+ 树；面试可补一句"URL 去重靠唯一索引在写入时挡住并发重复，数据库层兜底比应用层检查可靠"（`NewsService` / `FavoriteService` 的 DuplicateKeyException 处理就是配合这个）。

### ⭐2. 聚簇索引和非聚簇索引？什么是回表？
**答**：聚簇索引 = 主键索引，叶子节点存整行数据；二级索引（普通索引）叶子节点存的是**主键值**，用二级索引查到主键后再回主键索引查整行 = 回表。覆盖索引（查询列都在索引里）可以避免回表。

### ⭐3. 唯一索引和普通索引的区别？什么时候必须用唯一索引？
**答**：唯一索引在写入时强制校验唯一性（冲突报 `DuplicateKeyException`），普通索引不做校验。**业务上的"天然唯一"字段必须建唯一索引**（用户名、邮箱、文章 URL），否则应用层的"先查再插"在并发下必穿。
**结合项目**：`users` 表的 username/email、`news` 表的 url、`history` 表的 (user_id, news_id) 联合唯一——都是这个原则；应用层 `exists` 检查只做友好提示，真正的防线在数据库。

### ⭐4. 事务的 ACID？隔离级别有哪些？
**答**：原子性、一致性、隔离性、持久性。隔离级别从低到高：读未提交 → 读已提交 → **可重复读（MySQL 默认）** → 串行化。三个经典问题对应记忆：脏读（读到别人没提交的）、不可重复读（两次读值不同）、幻读（两次读行数不同）。InnoDB 在 RR 级别通过 MVCC + 间隙锁基本解决幻读。

### 5. 什么是 MVCC？（进阶但常问）
**答**：多版本并发控制——每行数据带隐藏的事务版本信息，读操作走快照不加锁，写才加锁，实现"读写不冲突"。一句话版：**读不加锁、读写不阻塞，靠数据多版本实现**。

### ⭐6. 索引什么时候会失效？
**答**：背最常用的五个——① like 以 `%` 开头；② 对索引列用函数/运算；③ 隐式类型转换（字符串列传了数字）；④ 联合索引不满足最左前缀；⑤ `or` 两侧有没有索引的列。
**加分句**：用 `EXPLAIN` 验证，看 type（至少 range 以上）、key（实际用了哪个索引）、rows（扫描行数）。

### ⭐7. `INSERT ... ON DUPLICATE KEY UPDATE` 是什么？
**答**：插入时若撞唯一索引则改为更新，一条语句保证幂等。
**结合项目**：`HistoryMapper.upsertHistory`——浏览历史并发写入不产生重复记录，全靠 history 表的 (user_id, news_id) 唯一索引 + 这条语句，是"数据库约束 + SQL 原子性"配合的教科书场景。

### 8. 逻辑删除和物理删除怎么选？
**答**：逻辑删除（打删除标记不真删）可恢复、有痕迹，但唯一索引会冲突、表膨胀；物理删除干净但不可逆。本项目的新闻/用户用逻辑删除（`deleted_at` + `@TableLogic`），收藏/历史用物理删除（因为要建联合唯一索引，软删会占用唯一键）——**这个取舍本身就是面试好答案**。

### 9. 深分页 `LIMIT 1000000, 10` 为什么慢？怎么优化？
**答**：MySQL 要扫描并丢弃前 100 万行。优化：① 用覆盖索引先定位起始 id 再关联（`WHERE id > 上页最大id`）；② 业务上限制翻页深度（项目里分页插件 `maxLimit=100` 是同一思想的入口版）。

### 10. 三大范式？什么时候反范式？
**答**：1NF 字段原子、2NF 消除部分依赖、3NF 消除传递依赖。实际业务常用**反范式换性能**（适当冗余避免联表）。一句话：范式是设计底线，反范式是性能权衡。

## 二、MyBatis / MyBatis-Plus

### ⭐1. `#{}` 和 `${}` 的区别？（必考，答错直接挂）
**答**：`#{}` 是**预编译占位符**（PreparedStatement 的 `?`），值带引号传入，能防 SQL 注入；`${}` 是**字符串拼接**，有注入风险。只在"表名/列名等不能参数化的位置"且值可控时才用 `${}`。
**结合项目**：`HistoryMapper` 的联表查询全部用 `#{userId}`；`last("LIMIT " + recentFingerprintScan)` 里 recentFingerprintScan 是内部 int 配置不是用户输入，所以安全——能主动讲这个区分是加分项。

### ⭐2. MyBatis、MyBatis-Plus、JPA 的关系一句话？
**答**：MyBatis 是半自动 ORM——SQL 自己写、结果映射帮你做；MyBatis-Plus 是 MyBatis 的增强（不改变原有），单表 CRUD、分页、逻辑删除等通用功能开箱即用，复杂 SQL 仍自己写；JPA/Hibernate 是全自动 ORM，SQL 全自动生成。国内业务项目主流是 MyBatis-Plus：**简单的不写 SQL，复杂的可控 SQL**。

### ⭐3. N+1 问题是什么？怎么解决？
**答**：查列表后循环逐条查关联数据，1 次查询变 N+1 次。
**结合项目**：`AiService.listSessions` 修复前后对比就是现成答案——原来每个会话单独查最后一条消息，改成 `selectLastMessages` 用**窗口函数 `ROW_NUMBER() OVER (PARTITION BY session_id ...)` 一次批量取回**。解决方案三条：JOIN 联表、批量 IN 查询、（MySQL 8）窗口函数。

### 4. MyBatis 的工作原理（简化版）？
**答**：接口方法 → Mapper 动态代理 → 找到对应 SQL（注解/XML）→ Executor 执行 → 结果按映射规则封装成对象。不用背源码，能讲通"为什么只写接口不用写实现类"（动态代理）即可。

### ⭐5. MyBatis-Plus 分页插件原理？怎么用？
**答**：本质是 **MyBatis 拦截器**——拦截查询语句，自动改写加 LIMIT、并额外发一条 COUNT。用法：配 `MybatisPlusInterceptor` 加入 `PaginationInnerInterceptor`，方法第一个参数传 `Page` 对象。
**结合项目**：`MyBatisPlusConfig`，且设了 `setMaxLimit(100)` 全局单页上限（防 pageSize 传超大值拖库）——这是很多人不知道的配置，面试提了就是亮点。

### 6. 逻辑删除在 MP 里怎么实现？
**答**：实体加 `@TableLogic` 字段 + yml 配置删除值/未删除值。之后 MP 生成的所有 CRUD 自动带 `deleted_at IS NULL` 条件、删除变 UPDATE。
**结合项目**：`deleted_at` 配的是 `NOW()`/`NULL`——MP 会把配置值原样拼进 SQL，所以能用数据库函数，删任何一条自动盖时间戳（可以现场让面试官看 `MYBATIS_LOG_IMPL` 打出的 SQL）。

### 7. 自动填充是什么？
**答**：实现 `MetaObjectHandler`，insert/update 时自动给指定字段填值（配合实体 `@TableField(fill=...)`）。
**结合项目**：`MyBatisPlusConfig` 的 `strictInsertFill(createdAt/updatedAt)`——所有表的时间戳全自动化，业务代码零侵入。

### 8. TypeHandler 是干嘛的？
**答**：Java 类型和 JDBC 类型的转换器。自定义一个可以完成复杂类型 ↔ 数据库列的自动互转。
**结合项目**：`BlockListTypeHandler` 把 `List<Block>`（正文块级 JSON）存成 LONGTEXT 字符串、查询时反序列化回来。**必提的坑**：实体上必须 `@TableName(autoResultMap = true)`，否则查询时 TypeHandler 不生效（新增字段能存不能查的经典事故）。

### ⭐9. "先查再插"有什么问题？怎么兜底？
**答**：检查和插入之间有时间窗，并发下两边都查不到、都插入成功 → 重复数据。正确姿势：**数据库唯一索引兜底 + 捕获 `DuplicateKeyException` 转成业务错误**（如 409 已收藏），应用层 exists 检查只用于提前给友好提示。
**结合项目**：`FavoriteService.addFavorite`、`AuthService.register` 都是这个模式，是本项目最值得讲的并发知识点。

### 10. 动态 SQL 常用标签？
**答**：`<if>` 条件拼接、`<where>` 自动处理 AND 前缀、`<foreach>` 遍历集合（in 查询/批量插入）、`<set>` 更新拼接。注解方式用 `<script>` 包裹。
**结合项目**：`AiMessageMapper.selectLastMessages` 的 `<foreach>` 拼 IN 列表。

### 11. select-then-update 的读改写为什么危险？
**答**：查询和写回之间别的线程可能也读了旧值 → 更新互相覆盖（丢更新）。
**结合项目**：新闻浏览量从"查出来 +1 再 updateById"改成 `UPDATE news SET views = views + 1`（`NewsMapper.incrementViews`）——**原子更新由数据库完成**，同类问题的另一解法是乐观锁（`@Version`）。

## 三、Redis

### ⭐1. Redis 为什么快？
**答**：四点——① 纯内存操作；② 单线程命令执行，无锁无上下文切换；③ IO 多路复用（epoll），单线程也能高并发连接；④ 高效数据结构（SDS、跳表、压缩列表等）。
**加分句**：Redis 6.0 引入多线程只用于网络 IO 读写，命令执行仍是单线程——保持原子性语义。

### ⭐2. 五大基本类型和应用场景？
**答**：String（缓存 JSON、计数器、分布式锁）、Hash（对象的部分字段读写）、List（消息队列、最新列表）、Set（去重、共同关注）、ZSet（排行榜、延迟队列）。
**结合项目**：项目里主要用 String——新闻详情缓存（`cls:news:detail:{id}`）、浏览去重标记、验证码计数，都是 `RedisTemplate.opsForValue()`。

### ⭐3. 缓存穿透、击穿、雪崩？（必考三连，定义+方案一起背）
**答**：
- **穿透**：查**不存在**的数据，缓存永远 miss，全打到 DB。方案：空值缓存（短 TTL）、布隆过滤器、参数校验。
- **击穿**：某个**热点 key 过期瞬间**，大量请求同时打 DB。方案：互斥锁（只放一个请求去重建缓存）、热点 key 不过期、逻辑过期。
- **雪崩**：**大批 key 同时过期**或 Redis 宕机。方案：TTL 加随机抖动、多级缓存、集群高可用、限流降级。
**结合项目**：TTL 兜底 + Redis 故障全降级放行（`NewsService` 每个 Redis 调用都 try-catch）——可以讲"我按雪崩思路做了可用性兜底：Redis 挂了业务可跑，只是没有缓存加速"。

### ⭐4. 缓存和数据库的一致性怎么保证？
**答**：标准答案是 **Cache-Aside：读→缓存 miss 查库回填；写→先更新数据库，再删除缓存**（删除而非更新缓存，避免写多读少时的无效计算和并发旧值覆盖）。它只能保证**最终一致**，不追强一致。
**结合项目**：`NewsService` 更新后删缓存，且做了**延迟双删**（`evictDetailCache`：删完 1 秒后再删一次，应对删后读旧值回填的窗口）；所有缓存都带 TTL 作为脏读上限的最终兜底。这套"不追强一致、追有界不一致"的表述很加分。

### ⭐5. SETNX 能干什么？过期时间为什么必须设？
**答**：`SET key value NX EX ttl` 是原子命令（对应 `setIfAbsent`），典型用途：分布式锁、防重提交、去重。
**结合项目**：浏览量防刷——`setIfAbsent("cls:news:viewed:{id}:{用户}", 1, 1小时)`，返回 false 说明 1 小时内已计过（`NewsService.incrementViews`）。
**必提**：不加 EX 的 SETNX 在持有者崩溃后锁永远不释放 = 死锁；要原子地"设值+过期"（`setIfAbsent(key, val, ttl, unit)` 一个调用完成，不能 SET 完再 EXPIRE 两步）。追问"锁过期但业务没执行完"→ 答"看门狗续期（Redisson）"，表示知道边界即可。

### ⭐6. Redis 过期了就立刻删吗？内存满了怎么办？
**答**：过期删除 = **惰性删除**（访问时检查）+ **定期删除**（后台抽样清理）组合。内存满 = 淘汰策略，常用 `allkeys-lru`（对全部 key 淘汰最近最少使用），默认 `noeviction`（写报错）。
**结合项目**：docker-compose 里 Redis 配的就是 `--maxmemory-policy allkeys-lru`，能说出来出处最好。

### 7. RDB 和 AOF？
**答**：两种持久化。RDB = 定时全量快照（文件小恢复快，可能丢最近数据）；AOF = 追加写命令日志（丢数据少，文件大恢复慢），生产常两者同开、用 AOF 保底。
**结合项目**：compose 里 `--appendonly yes`，即开了 AOF。

### ⭐8. INCR 做计数器/限流怎么用？
**答**：`INCR` 是原子自增，配合首次设置过期时间做时间窗计数。
**结合项目**：验证码每日限 10 条（`AuthService.checkSendRateLimit`）——**细节必讲**：increment 返回值等于 1 时才 `expire`（说明是本时间窗第一次），否则每次都会重置 TTL 导致永远数不满；对比"60 秒一条"用的是 `setIfAbsent`（存在即拒绝）。一个场景两种原语，选型理由要说清：EXPIRE 型适合"累计计数"，SETNX 型适合"间隔控制"。

### ⭐9. Redis 挂了怎么办？（考的是设计思维）
**答**：分场景回答，核心一句：**Redis 应该是增强件不是依赖件**。
**结合项目**：本项目所有 Redis 操作都有 try-catch 降级——浏览量照加不防刷、验证码限流放行、缓存 miss 直查库，只留 warn 日志。代价是失去保护能力，换取核心业务可用。反面对照：把登录 session 放 Redis 且无降级的服务，Redis 一挂全员登出。

### 10. RedisTemplate 取值强转的坑？
**答**：`RedisTemplate<String, Object>` 取出来是 `Object`，实际类型取决于序列化器（JDK 序列化整数可能是 Integer 也可能是 Long），直接 `(Long)` 强转可能 ClassCastException。
**结合项目**：`AuthService.verifyCode` 里 `cached instanceof Number n ? n.longValue() : 0`——真实修过的坑，讲出来比背八股有说服力。

## 四、怎么用这份文档

1. **第一遍**只看 ⭐ 题，能秒答的划掉，剩下的是你的真实差距；
2. 每个结合项目的点，**打开对应文件把代码跑一遍**（改坏实验最有效：改坏→观察→改回）；
3. 面试前只复习没划掉的题 + 每题第一句（先给结论再展开，面试官听的就是这个结构）；
4. 回答模板：**结论 → 原理一句话 → "我项目里就是这么用的，比如……"**——第三句是你对纯背题选手的降维打击。

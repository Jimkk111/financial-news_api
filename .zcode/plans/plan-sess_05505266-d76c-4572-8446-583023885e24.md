## 目标

将 crawler 从“依赖 LLM 自由发挥、失败仍返回 200、缓存/入库链路不可靠”的状态，提升为可启动、可观测、失败可感知、具备基本幂等和安全边界的企业级实现。保持现有 `/api/crawler/crawl` API 兼容，同时修正 `/api/crawler/crawl/stream` 的 SSE 契约。

## 已确认的主要根因

1. `CrawlerAgentConfig` 只判断 `crawler.agent.api-key` 属性是否存在，空字符串仍会激活配置，随后 Bean 创建时主动抛异常；应用没有 key 时可能直接启动失败。
2. `CrawlerController` 声明 `text/event-stream`，但返回普通 `Result`，`executeStream` 也只是同步调用，客户端无法获得真正 SSE。
3. `CrawlerAgentService` 吞掉所有工作流异常并返回普通结果，Controller 继续包装为 `Result.ok`，因此业务失败、LLM 失败和网络失败都表现为 HTTP 200。
4. Scraper/Processor/Writer 对 LLM 输出缺乏结构校验；`null`、畸形 JSON、非字符串字段可导致空指针或最终报告异常。
5. Wallstreet 列表返回 URI、Prompt 又要求传 ID、详情只按 URI 缓存，导致详情正文无法被 `saveNews` 命中。
6. `saveNews` 没有事务回滚保障；分类/标签“先查后插”存在并发竞态；URL 检查工具实际统计整张新闻表，未实现去重。
7. SSR 抓取未正确解析相对 URL，缺少请求超时、响应大小和 SSRF 防护；缓存无 TTL，可能造成内存增长。
8. `WorkflowContext` 统计字段不完整，失败阶段仍可能生成“完成”报告；用户 ID 没有传入工作流和新闻入库。

## 实施方案

### 1. 配置和可用性

- 增加明确的 `crawler.agent.enabled` 配置，默认关闭；保留 `CRAWLER_AI_*` 优先、`AI_*` 回退。
- 将 crawler Agent 配置改为仅在 `enabled=true` 且 API key 非空时创建。
- 让 `CrawlerAgentService` 通过 `ObjectProvider<CrawlerOrchestrator>` 获取可选编排器，避免 crawler 未配置时拖垮整个应用启动。
- 增加 crawler 专用错误码（未配置、执行失败、参数/来源不支持），未启用时接口返回明确的 503/4xx，而不是启动异常或伪成功。
- 关闭生产环境完整 LLM request/response 日志，改为仅记录 runId、阶段、耗时、数量和错误摘要；敏感内容不进日志。

### 2. 工作流状态和错误语义

- 扩展 `WorkflowContext`：加入 `runId`、`userId`、计划数量、当前阶段、成功/失败状态、错误列表和最终统计。
- `CrawlerOrchestrator` 接收并传递 `userId`，每个阶段进行显式状态更新和耗时记录。
- Planner/Scraper/Processor/Writer 的结果统一做 JSON 数组/字段校验：空值、`null`、非对象、超出文章上限、缺少 title/url 等直接进入失败状态并记录原因。
- 修复最终报告对任意 JSON 类型直接强转 String 的问题，使用安全字符串转换；失败阶段不再生成“工作流完成”文案。
- `CrawlerAgentService` 不再吞异常伪装成成功；同步接口继续返回现有 `role/content/sessionId` 字段，同时补充 `runId/status/success/statistics`，异常交给全局异常处理器返回正确 HTTP 状态。
- 修正统计摘要中的“计划篇数”和“抓取篇数”混用，并确保无文章/阶段失败时耗时和状态完整。

### 3. 真正可用的 SSE

- `CrawlerController.crawlStream` 改为返回 `SseEmitter`。
- `CrawlerAgentService.executeStream` 异步执行工作流，通过阶段回调发送 `started/progress/completed/error/done` 事件；客户端断开时停止继续发送并记录取消。
- 保持最终报告和 `sessionId` 字段，SSE 结束前发送统一 `[DONE]` 事件。
- 同步接口和 SSE 共享同一套核心执行方法，避免两条路径行为漂移。

### 4. 抓取安全和稳定性

- `CrawlerTools` 使用复用的 `HttpClient`，为连接和单次请求都设置超时。
- 请求响应改为受限字节读取，限制最大响应体大小；优先按响应头/HTML 元信息处理字符集，而不是固定 UTF-8。
- 增加只允许 `http/https`、禁止 localhost/环回/内网/链路本地/云元数据地址的 URL 校验；对当前支持的数据源使用 host allowlist，拒绝任意 URL SSRF。
- 统一 URL canonicalization：补全 `/`、`./`、`../`、`//host`、query 和 fragment，使用 Jsoup 的 base URI 或 `URI.resolve`。
- 对选择器无效、正文为空、正文低于最小质量阈值分别返回明确错误/低质量结果，不将空正文当作成功缓存。
- 将全局缓存改为带 TTL/容量保护的实现，并在 HTML 和文章缓存之间保持一致清理策略；本次不把大 HTML 传回 LLM。

### 5. Wallstreet 和通用缓存链路

- Wallstreet 列表统一返回 `id`、canonical URL 和 `type=api`，Prompt 明确详情工具以 `id` 为准。
- 详情成功后同时以文章 ID、返回 URI、canonical URL 写入同一缓存对象，`saveNews` 接受 ID 或 URL 均能命中。
- 对非法 articleId、空标题、空正文、超大 limit 做服务端校验和上限裁剪；channel 做 URL 编码。
- 修复 `checkUrlsExist`：解析 URL 列表后逐个查询实际存在记录，返回 total/existing/missing，而不是新闻总数。

### 6. 企业级入库和幂等

- 为新闻增加 canonical URL 字段及数据库索引/迁移脚本；对存量部署提供可执行的 ALTER 迁移，避免只改初始化 SQL。
- `saveNews` 在事务内完成新闻、分类、标签和关联写入；任一步骤失败整轮回滚。
- 分类/标签创建处理唯一键并发冲突后重新查询；标签先去重，避免重复关联触发唯一索引。
- 保存前按 canonical URL（并兼容已有标题/source 检查）做幂等判断，返回 `skipped:<existingId>`；把 `userId` 从服务传入上下文并落到 `news.user_id`。
- 通过明确的 ingestion 辅助方法隔离 LLM 工具参数和数据库写入逻辑，限制标题、来源、分类、标签和摘要长度，拒绝空标题/无正文新闻。
- 写入成功后清理新闻详情及分类/标签相关缓存；不绕过既有缓存契约造成旧数据长期可见。

### 7. 测试和验证

新增不依赖真实 LLM、数据库或外网的单元测试/fixture：

- 配置测试：无 key、仅通用 AI key、显式启用/禁用时的 Bean 和接口行为。
- Orchestrator 测试：Planner 异常、空/null/畸形 JSON、超上限、阶段失败、最终报告安全转换、统计状态。
- CrawlerTools 测试：URL 规范化、相对链接、非 200、超时/超大响应、SSRF、正文质量、Wallstreet ID/URI 双缓存、URL 去重。
- 入库测试：重复 URL、重复标签、分类/标签并发冲突、关联失败回滚、userId 传递。
- Controller/MockMvc 测试：同步失败的 HTTP 状态、SSE content type、阶段事件、错误事件和 `[DONE]`。
- 先运行 crawler 定向测试，再运行 `mvn test`、`mvn -q -DskipTests compile`，最后检查 `git diff --check`，确认不修改无关模块。

## 交付边界

- 不引入真实外部 API key，不调用外网，不把敏感配置写入仓库。
- 不把本次任务扩展为完整消息队列/分布式调度平台；会保留清晰的 `runId/status` 扩展点，当前以可靠同步执行和异步 SSE 为第一阶段。
- 不删除现有 API 字段；新增字段采用兼容式扩展。
